# Measurement and evidence

FontWitness 0.1.1 uses Playwright 1.64.0 and its Chromium 156.0.8078.4 (revision 1248). A public `BrowserContext.newCDPSession(page)` enables DOM/CSS. The collector traverses supported light-DOM TextNodes, retains remote objects with a scoped Runtime object group, and resolves each with `DOM.requestNode`. `DOM.describeNode` confirms nodeType 3. `CSS.getPlatformFontsForNode` supplies exactly `familyName`, `postScriptName`, `isCustomFont`, and `glyphCount`. No private Playwright fields are used.

The experiment in `scripts/feasibility.mjs` shows a 404 changing `Alegreya Sans` to a system monospace font while computed CSS stays `WitnessAlias, monospace`. It also shows four-level text and sibling TextNodes. A container call returns only its shallow layout text. FontWitness does not infer recursive coverage from that call: overlap is deduplicated by the TextNode object in the current capture and rule elements refer to canonical observation IDs.

Each CDP result retains its raw counts. Font identities can be unioned while preserving observation origins; counts are never summed across roots. A glyph count is not a Unicode character count, an accuracy percentage, or proof that tofu is absent. Backend node IDs only identify provenance within that session. Font URLs are not inferred from `isCustomFont` or joined to platform identities.

The browser is owned through public Playwright `launchServer`/`connect`, with a temporary loopback-only control endpoint that is never saved. Run deadlines and SIGINT terminate only this owned process. Graceful shutdown has a bounded budget with public `BrowserServer.kill()` as the fallback, so an unresponsive target cannot hold cleanup indefinitely. This is a local browser controller, not a hosted service.

Before navigation FontWitness installs font-request metadata listeners. It waits for DOMContentLoaded, the explicit trusted hook, an optional ready selector, and bounded `document.fonts.ready`. It captures two sets of DOM/font/layout signatures separated by rendering frames and a bounded stable window, retrying within maxAttempts. A font deadline or unstable window marks selected elements partial. Font readiness can settle after a request failure; intended font delivery still needs actual identity evidence and a contract.

Viewport screenshots never scroll the page. The collector rechecks the signature after the image; changes omit the inconsistent image and make the run partial. If a hook scrolls, it runs before readiness. Changes after the recorded window are outside the measurement. CSS, cache policy, animations, and font loading are not silently modified.

Direct scope selects only immediate supported text children. Subtree scope traverses ordinary light-DOM text descendants, with explicit limits. Whitespace and source-only script/style/template content are outside the policy. Hidden/no-layout text, empty targets, unavailable nodes, and reached limits have explicit unmeasured reasons. Known generated content, open shadow roots, SVG, canvas, iframes, and form controls make selected coverage partial. Closed shadow-root contents are outside this policy and cannot be enumerated by the light-DOM collector; a light-DOM verdict does not attest to shadow content.

`required` applies to each matched element; absence is proven only with complete measurement. An observed disallowed font is a known violation even in a partial capture. Missing minimum selector matches are a known violation. No required-font absence is fabricated from missing evidence.

Stable codes include `FONT_NOT_ALLOWED`, `REQUIRED_FONT_MISSING`, `SELECTOR_MIN_MATCHES`, `FONT_READY_TIMEOUT`, `UNSTABLE_CAPTURE`, `SCREENSHOT_STATE_CHANGED`, `TEXT_HIDDEN_OR_NO_LAYOUT`, `NO_SUPPORTED_TEXT`, `TEXT_NODE_LIMIT`, `TEXT_LENGTH_LIMIT`, `MATCH_LIMIT`, `DOM_TRAVERSAL_LIMIT`, `NODE_DETACHED`, `EMPTY_FONT_OBSERVATION`, `CDP_NODE_UNAVAILABLE`, `CDP_UNAVAILABLE`, `BROWSER_UNAVAILABLE`, `PREPARATION_TIMEOUT`, `RUN_TIMEOUT`, and `INTERRUPTED`.

Primary references: [CDP CSS](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/CSS.pdl), [Playwright CDP sessions](https://playwright.dev/docs/api/class-browsercontext#browser-context-new-cdp-session), [FontFaceSet.ready](https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet/ready), and [Chromium inspector implementation](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/inspector/inspector_css_agent.cc). The protocol has experimental behavior; browser upgrades require rerunning fixtures and changing capture policy when semantics change.

Capture policy v2 recognizes SVG by namespace, including prefixed elements, as an unsupported surface. Mixed supported HTML and SVG retains HTML observations but cannot claim complete coverage. Policy v1 captures from 0.1.0 are insufficiently comparable with v2 in either comparison mode; create a fresh capture deliberately.

Saved captures use a shared runtime parser in the CLI and public `compareRuns` boundary. Recorded settings and rule fields must be resolved; missing fields never receive config defaults. Observation IDs and rule IDs are unique. Element IDs are unique within each rule; the same canonical DOM root ID may be referenced by overlapping rules with different scopes. Reused root IDs must retain the same path. Element node references must be unique, resolve to observations, and agree with counts, measurement status, and text/structure fingerprints. Canonical global counts, readiness samples, coverage flags, and audit verdicts must agree with the recorded evidence. Optional rule results are checked against their recorded selections, actual font origins, and contracts.

Malformed or inconsistent evidence raises `CaptureInputError` and the CLI emits `INVALID_CAPTURE`, exit 2, before creating output. This differs from valid partial measurement, which remains available for descriptive comparison and returns 3. Unsupported policies, including identical v1 policies on both sides, and unsupported Chromium/Playwright pairs also return 3. Neither mode invents missing fonts or turns incomplete evidence into complete equality. Internal validation cannot authenticate the producer of a capture.

Doctor performs executable/version checks followed by sandboxed launch and a real `DOM.describeNode`/`CSS.getPlatformFontsForNode` TextNode probe. Safe reason codes distinguish missing browser, incompatible versions, denied launch, other launch failures, CDP measurement failures, cleanup failure, and interruption. An error log is inspected locally only to classify it; the JSON contains a code, a short action, versions, and successful font evidence, without raw errors or environment variables. Launch-denial tests inject failures at the browser boundary; they do not claim that a blocked OS environment can capture successfully.
